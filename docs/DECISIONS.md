## ADR-001：放弃复用，用 React 19 整体重写并清空 git 历史

- **日期**：2026-09-26
- **状态**：已采纳
- **背景**：原站基于 Vue 3.6-rc + Vuetify 4 + three.js + Pinia。依赖大量指向 `beta` 通道的
  `pnpm-workspace.yaml` overrides，站主判定其已无法维护，且明确表示不想复用任何部分。
- **考虑过的方案**：
  1. 在现有 Vue 项目上增量改造视觉
  2. 保留旧代码、另起新目录并行开发
  3. 删除全部旧实现，清空 git 历史，从零重建
- **决策**：方案 3。
- **为什么选这个**：站主的诉求是「换一种表达方式」而非「修修补补」。终端风格与通用 Web 风格
  在结构上不相容 —— 增量改造必然留下大量旧范式残骸（主题切换、Vuetify 组件体系、three.js 场景）。
- **为什么不选其他**：方案 1 会持续支付旧依赖的维护成本；方案 2 会留下两套并存的认知负担。
- **后果**：旧站的全部未提交改动被永久丢弃 —— **唯一例外是 `LICENSE.md`**（见 ADR-007）。
  云端仓库由站主自行清理。
- **何时重新审视**：不需要。这是一次性的方向选择。

## ADR-002：字符画一律使用纯半角 ASCII，禁用制表符与方块元素

- **日期**：2026-09-26
- **状态**：已采纳
- **背景**：终端风格最自然的选择是制表符 `─│┌┐└┘` 与方块元素 `█░▒▓`。但字符画的对齐
  完全依赖「每个字符占据相同的 advance 宽度」。
- **调查**：`@fontsource-variable/jetbrains-mono` **按 unicode-range 分片**，共
  latin / latin-ext / greek / cyrillic / cyrillic-ext / vietnamese 六个分片，
  **没有任何一个包含 U+2500（制表符）或 U+2580（方块元素）区段**。
  也就是说，画里一旦出现这些字符，浏览器会回落到系统等宽字体 —— 而 JetBrains Mono 与
  Menlo / Consolas / 各系统中文字体的 advance 宽度并不相同。**整幅画当场错位。**
- **考虑过的方案**：
  1. 使用制表符，接受在部分平台错位
  2. 自托管完整版 JetBrains Mono（约 200KB 且需自行子集化）
  3. 全部改用纯半角 ASCII（`+ - | / \ _ . ' * = #`）
- **决策**：方案 3。
- **为什么选这个**：零风险，且**更贴合真正的终端字符画传统** —— 制表符绘图是「现代终端」的
  产物，而 80 年代的 BBS / ASCII art 本来就是用这些符号画的。风格上不亏。
- **为什么不选其他**：方案 1 是拿核心视觉冒险；方案 2 为一个可替代的视觉细节引入显著的
  字体体积与子集化维护成本。
- **后果**：
  - `tests/unit/art/art.test.ts` 有测试守住「不含全角字符、不含制表符、仅含可打印 ASCII」
  - 噪点字符池通过 `charset.ts` 的 `resolvePool` 在运行时检测并降级（字体缺字时退回纯 ASCII）
  - 需要中文标注时，用 `grid.ts` 的 `columnToIndex` 在画外单独定位
- **何时重新审视**：若要引入自托管的完整等宽字体（含 CJK 与制表符）。

## ADR-003：用两层 `<pre>` 互补渲染，而不是 clip-path / canvas / WebGL

- **日期**：2026-09-26
- **状态**：已采纳
- **背景**：需要表达「两级亮度」—— 已解码格显示目标字符（亮、有辉光），未解码格显示乱码
  （暗、无辉光）。最初的方案是「双层 `<pre>` + `clip-path` 揭开」。
- **考虑过的方案**：
  1. 双层 `<pre>` + `clip-path` 动画
  2. `<pre>` 内逐字符 `<span>` 上色
  3. `<pre>` 亮层 + canvas 暗层
  4. 纯 canvas 渲染
  5. WebGL / three.js 实例化
- **决策**：**方案 3 的简化版** —— 两层 `<pre>`，互补填空格。
- **为什么选这个**：
  - 方案 1 被证伪：`clip-path` 只接受**几何形状**，而「哪些格子已解码」是**随机散点数据**。
    硬要用 `path()` 拼 1500 个子路径，每帧重写几十 KB 且触发撤销抗锯齿，会在 CRT 画面上
    留下网格状暗线。
  - 方案 2 不可行：`<pre>` 内是**单个文本节点**，CSS 无法对文本节点内部的字符分别着色。
  - 方案 4 会丢失可选中、可被屏幕阅读器与搜索引擎读取的能力 —— 本项目的内容是有价值的。
  - 方案 5 对纪念站是过度工程。
  - 两层 `<pre>` 相比「亮层 + canvas 暗层」省掉了最易出错的一环：canvas 的栅格尺寸必须与
    字体度量精确对齐。既然暗层本来就不带辉光，用 `<pre>` 的代价可以忽略。
- **关键约束**：两层必须**互补划分**，而不是两层都画满靠 z-order 叠 —— 字符之间有空隙，
  画满的话乱码会从字形缝隙里透出来，结果是「脏」而不是「亮」。
- **后果**：亮层单调递增，只在真的解码了新格时重写 DOM，重绘频率从 60Hz 降到十几 Hz。
- **何时重新审视**：若需要 3 级以上的亮度层次（更细腻的渐显），届时 canvas 是正解。

## ADR-004：引入全局动画导演，把「同屏 ≤3 个循环」变成可执行的约束

- **日期**：2026-09-26
- **状态**：已采纳
- **背景**：若每个组件各自 `requestAnimationFrame`，则「同屏活跃循环上限」只是一句**口号** ——
  没有执行者，也没有全局预算、优先级、抢占与统一的降级策略。
- **决策**：模块级单例 `director`，持有唯一的 rAF、演员注册表与优先级预算。
- **为什么选这个**：
  - 预算约束第一次变得**可测试**（`tests/unit/engine/director.test.ts` 直接断言每帧只推进 3 个）
  - `document.hidden`、`prefers-reduced-motion`、画质降级的处理收归一处，不分散到各组件
  - `advance(dt)` 公开，使单测可以**注入手动时钟** —— 「跑 60 帧」就是循环调 60 次，完全确定
- **后果**：组件不再自己持有循环，只提供 `tick` 与 `settle`。`elapsed` 属于演员，
  因此「暂停」就是「不调用 tick」，进度天然保留。
- **何时重新审视**：若出现需要独立时间轴编排的复杂场景（届时可能引入 motion 的 timeline）。

## ADR-005：不引入 react-router，也不引入 motion

- **日期**：2026-09-26
- **状态**：已采纳
- **背景**：单页滚动叙事。最初的方案里列了 `motion`（framer-motion 后继）用于滚动编排。
- **决策**：两者都不引入。
- **为什么选这个**：
  - **router**：没有路由需求。少一个依赖，且顺带免除了 GitHub Pages 的 SPA 404 回退问题 ——
    构建产物只有 `index.html` 与静态资源，`dist/` 直接可用。
  - **motion**：本项目 90% 的动画是自研的 rAF 字符解码，motion 帮不上忙；剩下的滚动入场
    用 IntersectionObserver + CSS transition 即可覆盖。省下 40KB+ gz 与一整套滚动订阅。
- **为什么不选其他**：终端风格的动画本质是**离散帧**（字符替换），不是**连续插值** ——
  这恰好是 CSS/motion 这类补间动画引擎不擅长的领域。
- **后果**：运行时依赖只有 `react`、`react-dom` 与一个字体包。
  构建产物 JS 约 81KB gz。
- **何时重新审视**：若编排复杂到 CSS 与导演都表达不了（串行时间轴、弹簧物理），
  届时引入 `motion` 并配 `LazyMotion` 控制体积。

## ADR-006：采用 TypeScript 7，并接受其与 5.x 的配置差异

- **日期**：2026-09-26
- **状态**：已采纳
- **背景**：TS 7 是原生（Go）编译器的重写版，语言特性兼容，但工具链与部分配置项可能有缺口。
  这是本项目在选型时识别出的主要风险之一，并预设了回退到 5.9.x 的路径。
- **实际结果**：安装后立即验证，**仅有一处差异** —— `baseUrl` 被移除
  （错误 TS5102，提示改用 `paths`）。移除后 `tsc --noEmit`、`vitest`、`vite build` 三者贯通。
  **未触发回退。**
- **决策**：继续使用 TS 7.0.2。
- **后果**：
  - `paths` 现在相对于 tsconfig 所在目录解析，不再需要 `baseUrl`
  - CI 中保留**独立的类型检查步骤**，不只依赖编辑器
- **何时重新审视**：若后续引入的工具链（如某个代码生成器）不兼容 TS 7 的编译 API。

## ADR-007：保留 `LICENSE.md`，并做成 `cat LICENSE` 终端彩蛋

- **日期**：2026-09-26
- **状态**：已采纳
- **背景**：站主决定删库并「不留备份」。清理前盘点发现，仓库根目录的 `LICENSE.md` 并非模板
  许可证，而是站主亲手写的《杏仁鹿与咕猫猫一生一世专属许可证》——
  一份仿 GPLv3 格式、七条条款的情书。
- **决策**：**在执行删除前先将它抢救出来**，作为唯一豁免「硬删」的文件保留，
  并在新站里做成页脚终端的 `cat LICENSE` 命令。
- **为什么这么决定**：站主做出「硬删」判断时的理由是「页面已经烂完了」，而这份文件
  不属于「烂完了」的范围。它同时是：最具情感价值的资产，以及最贴合终端主题的彩蛋形式
  —— 一份法律文书式的文本，在终端里被 `cat` 出来。
- **实现**：以 Vite 的 `?raw` 直接导入仓库根的 `LICENSE.md`。
  **单一内容源，零重复** —— 它同时是仓库的规范许可证文件与站内彩蛋的数据源。
- **后果**：`LICENSE.md` 必须保留在仓库根目录。若删除，`pnpm build` 会失败。
- **何时重新审视**：不需要。

## ADR-008：`vitest` 锁定到 5.0.1（而非最新的 5.0.2）

- **日期**：2026-09-26
- **状态**：已采纳
- **背景**：`vitest` 的 peer 依赖要求 `@vitest/coverage-v8` **精确等于**同一版本号。
  npmjs 上两者都是 5.0.2，但国内镜像 `registry.npmmirror.com` 的 `coverage-v8` 只同步到 5.0.1。
- **考虑过的方案**：
  1. 绕过镜像，对 vitest 相关包单独走 npmjs
  2. 放弃覆盖率
  3. 两者一起降到成套的 5.0.1
- **决策**：方案 3。
- **为什么选这个**：只差一个补丁号，却保住了全量镜像加速
  （站主的操作规范要求下载优先使用国内镜像）。覆盖率是纯逻辑层的主要质量手段，不应放弃。
- **后果**：`package.json` 中这两个包使用**精确版本号**（无 `^`），避免解析回更高版本而失配。
- **何时重新审视**：镜像同步到 5.0.2 之后，可改回 `^`。

## ADR-009：提亮 `--amber-dim` 以满足 WCAG AA（axe 实测驱动）

- **日期**：2026-09-26
- **状态**：已采纳
- **背景**：设计令牌原定 `--amber-dim: #9c6a1c`，并在文档中标注「仅用于装饰性乱码，
  禁止用于叙述正文」。接入 `@axe-core/playwright` 后实测：
  **对比度 4.27:1，未达 AA 要求的 4.5:1** —— 差一点，但确实是 serious 级违规。
- **决策**：
  - `--amber-dim` 提亮到 `#a87320`（实测 4.87:1）
  - 与亮层 `#ffc75a`（12.9:1）仍有 **2.6 倍**差距，解码的明暗层次不受影响
  - `--amber-ghost` 明确降格为**仅限非文字用途**（边框、网格）
  - 时间线标题原先误用装饰色，改用正文次级色 `--text-secondary`（7.8:1）
  - 尾声星光原先靠 `opacity: 0.85` 压暗，把对比度连带压到 3.35:1；改由色值本身控制
- **为什么这么决定**：装饰性文本确实处在 WCAG 的灰色地带，但既然能只付出 2.6 倍→仍在安全区
  的代价就消除它，就没有理由留着。
- **后果**：`e2e/with-gu.spec.ts` 的无障碍用例会在出现 serious 违规时失败，形成回归防线。
- **何时重新审视**：若视觉上觉得乱码层不够暗 —— 那时应改的是**亮层更亮**，而不是暗层更暗。

## ADR-010：`CNAME` 移入 `public/`

- **日期**：2026-09-26
- **状态**：已采纳
- **背景**：原仓库的 `CNAME`（内容 `with-gu.xrl.im`）位于**仓库根目录**。
  Vite 只把 `public/` 的内容原样拷贝进 `dist/`，根目录的 `CNAME` **不会被拷贝**。
  由于本项目走 GitHub Actions（上传 `dist` 作为 Pages artifact）而非分支部署，
  这意味着**每次部署后自定义域名都会失效**。这是旧站一直带着的隐患。
- **决策**：`CNAME` 移入 `public/`，`dist/CNAME` 由构建自动产生。
  同时新增 `public/.nojekyll`，避免 Jekyll 处理下划线开头的文件。
- **后果**：`dist/CNAME` 的存在是部署正确性的必要条件，已在验证步骤中人工确认。
- **何时重新审视**：不需要。

## ADR-011：`pool`（字符池）不得进入动画 effect 的依赖数组

- **日期**：2026-09-26
- **状态**：已采纳
- **背景**：一次「本地 E2E 全绿、CI 全红」的事故。
  CI 上 `data-reveal-state` 永远停在 `running`，44 次轮询无一变化。

  成因是一条**只在特定机器上才闭合**的因果链：
  1. `App` 初值 `DEFAULT_POOL`，字体就绪后 `measureCellMetrics()` 实测并把结果灌回 state；
     实测判定「扩展字符与 ASCII 不等宽」时结果是 `ASCII_POOL` —— 与初值**不同**。
  2. 该差异使 `useCharAnimation` 的注册 effect 重跑：注销旧演员、注册新演员（`visible: false`）。
  3. 而同步可见性的 effect 依赖 `[id, play, reducedMotion]` 一个都没变，**不会重跑** ——
     新演员永远等不到 `setVisible(true)`。
  4. 导演 `advance()` 发现无人可见便 `stop()`，动画永久冻结。

  两个前提**缺一不可**，且都不在开发机上成立：实测要判定降级（取决于机器装了哪些字体），
  实测还要晚于动画开始（冷字体缓存 + 慢机器；开发机字体早已进缓存，实测总赶在动画前面）。

- **考虑过的方案**：
  - (a) 把 `play` 一并放进注册 effect 的依赖 —— 会顺带把动画重启，退化为「离开视口即重播」，与设计相悖；
  - (b) 实测失败时干脆不降级池子 —— 会把「宁可朴素，不可错位」的既有保护拆掉；
  - (c) **釜底抽薪：承认 `pool` / `play` 都不是排程参数，走 ref 不进依赖**。
- **决策**：采纳 (c)。`pool` 只决定乱码层取哪些字符、`play` 只决定可见性，二者都用 ref 传递；
  同时注册演员时以 `visible: playRef.current` 与最新可见性对齐，把「注册后可能等不到
  `setVisible`」这条隐患从结构上堵死，而不是依赖「依赖数组恰好没变」这个巧合。
- **为什么不选其他**：(a) 把一次渲染参数的修正放大成一次进度重置；(b) 用错误换稳定。
- **后果**：
  - `e2e/with-gu.spec.ts` 新增回归用例，用「伪造测量结果 + 拖慢字体」把上述两个前提
    在任何机器上造出来 —— 修复前它能复现出与 CI **逐字相同**的报错。
  - `tests/unit/hooks/useCharAnimation.test.tsx` 新增两条纯单测，不依赖时序也能守住。
  - `App` 把实测结果写到 `<html data-char-pool>`，让「这台机器属于哪一侧」变成可观测信号
    （Playwright trace 与真机 DevTools 都能直接看到）。
- **何时重新审视**：向 `useCharAnimation` 增加任何新参数时 —— **先问它是不是排程参数**。

## ADR-012：E2E 与部署并行，E2E 不再阻塞发布

- **日期**：2026-09-26
- **状态**：已被 ADR-017 取代（E2E 后来整个退出了 CI）
- **背景**：`deploy` 原为 `needs: [verify, e2e]`。E2E 一红，新版本就发不出去 ——
  E2E 跑得慢时也会一并拖住发布。
- **决策**：`deploy` 改为 `needs: verify`，与 `e2e` 并行。E2E 从**发布闸门**降级为**事后信号**。
- **为什么**：站主明确选择「让新版本该发就发，不被 E2E 的时长与偶发 flaky 干扰」。
- **代价（必须知情）**：**E2E 挂了也照样部署**。发布产物只保证通过类型检查、Lint、单测与构建，
  不保证端到端可用。§ADR-011 那次事故若发生在此约定之下，坏版本会直接上线。
- **缓解**：如需既并行又不丢闸门，在仓库 branch protection 里把 `E2E` 设为
  **required status check** —— PR 依旧合不进来，但 main 上的部署不被它阻塞。
- **后果**：`.github/workflows/ci-cd.yml` 的注释里写明了这一取舍，避免日后被误当成配置疏漏。
- **何时重新审视**：若出现「E2E 红着上线、用户先发现」的情况，应立即收回本决策。

## ADR-013：动画的墙上时长不得随帧率漂移

- **日期**：2026-09-26
- **状态**：已采纳
- **背景**：`MAX_DELTA_MS` 原本是 50ms。它为一件事存在：后台标签页 rAF 完全停止，
  回来后第一帧的 delta 可能是几十秒，不截断就会「瞬间跳到终态」。
  但它同时**决定了动画在慢机器上的墙上时长** —— 被截掉的时长不会补回来。
  60Hz 的帧长是 16ms，取 50ms 意味着低于 20fps 就会被截断：2.6s 的动画在 10fps 的机器上要跑 5.2s。
- **决策**：放宽到 200ms（只有低于 5fps 才截断）。真正处理挂起的是 `visibilitychange`
  重置时间基准，截断只是第二道防线，因此给得起这个宽松度。
- **为什么不选其他**：维持 50ms 等于把「动画时长」变成一台机器帧率的函数 ——
  正是「本地通过、CI 超时」那类环境相关故障的温床。
- **后果**：`tests/unit/engine/director.test.ts` 新增断言，锁住「100ms / 200ms 的帧长原样通过」。
  挂起后回来最多跳过 200ms 的动画，对最短 1.6s 的动画是可接受的。
- **何时重新审视**：若出现「切回标签页时动画明显跳帧」的实机反馈。

## ADR-014：正片是一个 fixed 的终端窗口，不是铺在黑底上的卡片流

- **日期**：2026-09-26
- **状态**：已采纳
- **背景**：PRD 写的是「像坐进一台老式终端」，但正片原本的形态是**七个各自带边框、
  各带背景渐变的卡片**铺在页面上。读起来像「用了终端配色的网页」，迟迟戴不上
  「正在读一台终端」的语境。卡片是网页的原生语汇，终端不是。
- **决策**：
  1. 正片（时间线 + 尾声 + 命令输出）整体收进**一个 `position: fixed` 的窗口**，
     标题栏与命令行常驻，滚动发生在窗口内部的屏幕（`[data-terminal-screen]`）里；
  2. 七个节点不再是卡片，改成**同一段输出流**：每个节点由一行 `cat milestones/xx.log`
     开启，节点之间一条虚线断开，语义上仍是 `<ol>` / `<li>`。
- **为什么窗口要 fixed**：若窗口随内容延伸，边框会跟着内容一起滚走，中段完全看不到窗口
  的顶与底 —— 沉浸感又没了。fixed 让「页面本身不滚动」成为**结构事实**而不是约定。
- **代价（逐条都必须知情）**：
  - **移动端横向溢出的断言换了测量对象**。文档流不再滚动后，
    `document.documentElement.scrollWidth` 永远是干净的，测不出任何东西；
    真正的测量对象是窗口的屏幕。E2E 现在两个容器都测。
  - **屏幕成为滚动容器，必须 `tabindex="0"`**，否则 axe 的
    `scrollable-region-focusable` 直接判 serious（键盘用户滚不动它）。
  - **入场动画会把 axe 判成一片红**。`window-in` 是 opacity 动画，动画未落定的那一帧里
    整窗文字被当成半透明色计算：#ffab2e 被算成 #463010，凭空报出十几条
    `color-contrast` serious。因此窗口暴露 `data-enter-state`，
    E2E 等**状态**不等时间（沿用 `data-reveal-state` / `data-armed` 的既有做法）。
  - **色值的达标结论跟着底色走**。标题栏与命令行的底是 `--bg-raised`（比 `--bg-void` 亮），
    `--amber-dim` 在其上只有 4.47:1，差 0.03 掉出 AA。这两处的次级文字改用
    `--text-secondary`（7.12:1），而不是去改动全局色阶 —— 与 ADR-009 同一个教训。
- **后果**：
  - `components/terminal/` 下五个文件：`TerminalWindow`（外壳 + 屏幕 context）、
    `TerminalSession`（会话状态与命令解析）、`TerminalOutput`（屏幕内的历史输出）、
    `TerminalPrompt`（常驻底部的提示符）。旧的 `TerminalFooter` 随之拆解。
  - 命令历史与输入框**不在同一个 DOM 位置**（前者随正文滚动，后者常驻），
    所以会话状态必须提到窗口之上 —— 这是这次拆分的唯一原因。
  - `content/commands.ts`：命令说明与提示文案按全局规则 1 从组件里移出。
- **何时重新审视**：若要给首屏也套上这层外壳 —— **不要**。开机时窗口尚未出现，
  开机序列本身就是「窗口出现之前的那块黑屏」，这是刻意的先后关系。

## ADR-015：节点是滚动驱动的一段会话，不是预先摆好的版面

- **日期**：2026-09-26
- **状态**：已采纳
- **背景**：ADR-014 把正片收进了一个终端窗口，但窗口**里面的内容**还是「一滚到就全在那儿」——
  命令、编号、日期、标题同时出现，只有字符画在动。看起来像版面早就排好了，
  而不是有一台终端正在回显。CRT 覆盖层当时也只有静止的扫描线加偶发闪烁，
  少了「正在通电」的那点活气。
- **决策**：
  1. 每个节点是一段**会话**，三个阶段挂在 `data-phase` 上：
     `idle`（还没滚到，屏幕上什么也没有）→ `typing`（命令被逐字敲出来）
     → `output`（敲完，结果才依次划出）。字符画是 `output` 的产物。
  2. **输入与输出都是伪流式**：命令逐字符揭开（CSS `clip-path` + `steps()`），
     结果区的三行短信息依次划出、叙述逐行揭开。**唯一的例外是字符画**——
     它整块出现（不做流式），然后跑自己那套解码动画。
     它本来就是「一块像素」，逐行流式反而会毁掉它的揭示语言。
  3. 进入窗口时屏幕是**空的**：先 `cat timeline.log` 敲完、标题吐出来，
     才轮到第一条节点开口。这半秒的先后就是「终端刚醒来」与「版面早就摆好了」的分界线。
  4. 覆盖层加一层 hum bar：一条缓慢下滚的亮带，老显示器受市电干扰的样子。
     它是整套滤镜里**唯一会动**的一层——扫描线是静止的，暗角是静止的。
- **代价（逐条都必须知情）**：
  - **时钟不能挂在会抖的输入上**。`started` 来自 IntersectionObserver，
    元素贴着 `rootMargin` 那条线时会反复进出；计时器随之反复
    `clearTimeout` + 重设，只要抖动周期短于打字时长，**这一行就永远敲不完**——
    而「敲完才输出」意味着整个节点的标题与字符画永不出现。
    E2E 里 `nanjing` 节点就这么卡死过。修法是把「已经开过口」做成单向事实，
    `tests/unit/hooks/useCommandTyping.test.tsx` 里有专门的回归用例
    （把实现改回旧写法，它立刻变红——验过）。
  - **结果区在 `idle` 就占着布局**（靠 `clip-path` 隐藏）。所以滚到节点时
    会先看到一片空白，再被内容填上。这是刻意的：揭开过程绝不改变布局，
    否则就是 CLS 与滚动锚定跳变。
  - **字符画的 t=0 帧在挂载时就写好了**，必须靠 `.art` 的 `visibility` 挡住，
    否则「滚到就有东西」当场漏底。用 `visibility` 而不是 `opacity`——
    半透明的那一帧会让 axe 判对比度不达标（§ADR-014 的教训）。
  - **干扰波要停在「干扰」而不是「遮住字」**：峰值透明度压在 7% 以内；
    `prefers-reduced-motion` 与 `prefers-reduced-transparency` 下整层移除，
    而不是让它停住——停住就是一条亮带永久横在屏幕上，比动着更难看。
  - 「七个节点齐备」那条 E2E 原本就要 27 秒，每个节点多一秒就顶破
    Playwright 默认的 30 秒上限。改 `test.slow()`。
- **后果**：`hooks/useCommandTyping.ts`（阶段机）· `AsciiArt` 新增 `armed`
  （`play` 与门，走在既有的 ref + `setVisible` 路径上，不会重启注册 effect）。
- **何时重新审视**：若「等命令敲完」开始成为等待负担——那是一切节奏参数的调节旋钮。

## ADR-016：开机序列有 3 秒的耐心，台词池退场

- **日期**：2026-09-26
- **状态**：已采纳
- **背景**：开机自检六行、每行 180ms，不到一秒就滚完了；按钮从第一帧起就在等你按。
  一按就进只能说明这是个网页，不是一台要启动的机器。另外，旧站 `DynamicLine.vue`
  留下的那句随机台词与自检日志的机械感不是一路 —— 一边在报内存，一边在说俏皮话。
- **决策**：
  1. 自检每行间隔 500ms，整段六行 3 秒；**START 在 3.4 秒才交出来**。
  2. 按钮在此之前是 `visibility: hidden`：不是「看得见但点不动」，
     而是**压根不在无障碍树里** —— 键盘用户也不会 Tab 到一个还在加载的按钮上。
  3. 按钮从 `[ ENTER ]` 改名为 `[ START ]`。
  4. 台词池（`content/quips.ts`）连同它的渲染一起移除。
- **代价（逐条都必须知情）**：
  - **`steps(n, end)` 会在浮点边界上卡在倒数第二步**。实测 delay 为 1s 时，
    `Animation.currentTime` 停在 `1000.9999999999999`、`progress` 是
    `0.9999999999998899`，而 `jump-end` 在 progress < 1 时输出的是**起始值** ——
    那一行永远是 `opacity: 0`，动画却已经 `finished`，`fill: forwards` 也兜不住。
    改用 `steps(n, jump-start)`：它在 progress > (n-1)/n 时给结束值，容得下这点误差。
    **闪烁类动画（caret / cursor）要的恰好相反** —— 它靠「在 50% 处跳到透明」，
    那些地方必须仍是 `jump-end`。两者不能一把改（第一版就是一把改的，当场把光标闪没了）。
  - **按钮交出来的时刻由 CSS 动画的 delay 持有**，JS 只监听 `animationend`。
    两边各算一次迟早会不一样，所以 `TOTAL_MS` 在 `BootScreen.tsx` 里只定义一次，
    喂给 CSS 也喂给状态属性。
  - `data-boot-state` 是新的等待锚点。代价是 E2E 每条用例多等 3.4 秒 ——
    32 条下来总时长从 ~48 秒涨到 ~1.1 分钟。
- **何时重新审视**：若出现「每次进来都要等三秒」的抱怨。节奏在 `LINE_STEP_MS` / `SETTLE_MS`。

## ADR-017：CI 不再跑 E2E

- **日期**：2026-09-26
- **状态**：已采纳（取代 ADR-012）
- **背景**：ADR-012 已经先把 E2E 从「发布闸门」降级为「事后信号」—— 它不再阻塞部署。
  既然如此，它在 CI 里剩下的作用就只有「事后报个信」。而它现在跑一轮要一分钟出头
  （还在涨：每加一段会话就多几秒），外加浏览器下载与 flaky 的重试成本。
- **决策**：把 `e2e` job 整个从 `.github/workflows/ci-cd.yml` 移除。
  流水线只剩 `verify`（类型检查 / Lint / 单测 / 构建）→ `deploy`。
  本地 `pnpm test:e2e` 照常可用，Playwright 的配置与用例一条没删。
- **为什么**：站主认为「CI 里跑一遍再报个信」的收益不值那个时长与不确定性 ——
  真要端到端验证，本地跑一遍看得还更清楚。
- **代价（必须知情）**：**CI 完全不碰端到端**。四道闸全绿也可能上线一个端到端崩掉的版本。
  ADR-011 那类「本地全绿、CI 全红」的环境相关故障（字体、渲染节流），
  从此在 CI 侧不会再被拦下 —— **只会在本地暴露**，也就更依赖发版前自己跑一遍。
  可以说这条决策把 CI 的职责收敛成「构建与静态检查」，把 E2E 降为纯本地工具。
- **何时重新审视**：若出现「上线后才发现端到端坏了」的情况；
  或 E2E 的时长回到十几秒量级，那时它便宜到可以随时再放回去。
