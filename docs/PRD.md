# PRD — 咕鹿小屋纪念站

## 产品目标

把一段私人恋爱记忆，做成一个**可以长期存在、无需维护、不依赖任何第三方服务**的静态页面。

它首先是为两个人做的：访客打开它，应该像坐进一台老式终端，看着一段记忆被逐字符地读取出来。
技术上的所有取舍都服从这一点 —— 不是做一个「用了终端配色的网站」，而是让**读取记忆这件事本身**
成为交互。

## 用户与使用场景

- **目标用户**：站主与伴侣本人；以及被分享链接的少数亲友。
- **典型场景**：
  - 在纪念日打开，从开机序列一路读到底
  - 被分享到聊天软件里，对方点开后能立刻看懂「这是什么」
  - 手机上打开（占比不低于桌面），单手滑动读完

## 核心问题

| 问题                       | 说明                                                               |
| -------------------------- | ------------------------------------------------------------------ |
| 记忆会随平台消失           | 不依赖任何可能关停的服务；纯静态，可无限期托管                     |
| 通用网页模板承载不了私人性 | 需要一种**只有这段关系才成立**的表达方式                           |
| 动画容易沦为装饰噪音       | 动画必须承载信息：每一处动效都在「揭示」内容，而不是「入场」       |
| 无障碍常被牺牲             | 伴侣与家人并非都是技术用户；减弱动态效果、键盘、屏幕阅读器都要能用 |

## 功能及其意义

| 功能             | 解决什么                             | 为什么需要                                                                                                   |
| ---------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| 开机自检序列     | 建立「这是一台终端」的语境           | 让后续所有字符动画都有解释；同时是解锁音频所需的用户手势                                                     |
| 终端窗口外壳     | 让「这是一台终端」从配色变成**结构** | 正片整体收在一个窗口里：标题栏与命令行常驻，内容在窗口内滚动。没有它，页面只是「用了终端配色的网页」         |
| 七个时间线节点   | 承载全部叙事                         | 每个节点是一个可独立回忆的事件，而非一条连续流水账                                                           |
| 伪流式会话       | 让「读取」成为过程而不是版面         | 滚到才敲命令、敲完才吐结果；命令逐字揭开，结果依次划出。字符画是唯一的例外——它整块出现，然后跑自己的解码动画 |
| 随机字符解码动画 | 让「记忆被读取」可被看见             | 这是全站的核心表达；四种揭开顺序分别对应不同节点的情绪                                                       |
| 逐节点专属字符画 | 为每个事件提供视觉锚点               | 直播间的显示器、表白的爱心、奔现的高铁、车祸的心电监护……                                                     |
| 减弱动态效果分支 | 让对动效敏感的人能用                 | 首帧即终态，内容**完整可读**，不是「跳过内容」                                                               |
| 命令行终端       | 允许访客主动探索                     | `cat LICENSE` 给出站主手写的《一生一世专属许可证》全文                                                       |
| 御神签 `fortune` | 一个轻量的、属于这个站的仪式         | 保留旧站的抽签传统，带 8 小时冷却                                                                            |

## 功能之间的关系

```
开机序列 ──受控入口──▶ 时间线（七个节点）
    │                      │
    │                      ├──▶ 尾声（在一起的天数，实时）
    └── 自检日志逐行滚出     │
                          └──▶ 命令行 ──▶ cat LICENSE / fortune / help

    ↑ 以上正片内容全部活在同一个终端窗口里：
      标题栏与命令行常驻，只有屏幕在滚动
```

- 开机序列是**唯一门槛**：不进入就不能读到时间线。它有 3 秒的耐心 ——
  足够建立「一台老机器正在启动」的语境，又不至于让人以为卡住了。
  START 在此之前既不可见、也不可聚焦：不是「看得见但点不动」。
- 开机序列本身**不套窗口外壳** —— 那时窗口还没出现，它是「窗口出现之前的那块黑屏」。
- 尾声的「在一起 N 天」由真实的当前时间算出，是**全站唯一会随时间变化的内容** ——
  它让页面即使无人维护，也仍然是「活」的。星空则在微微闪烁，是它唯一持续的呼吸。
- 命令行不参与主线叙事，是给愿意多停留一步的人准备的。它的输出落在屏幕内容流的末尾
  （随正文滚走），只有提示符常驻窗口底部 —— 真终端就是这样分工的。

## 范围与非目标

**范围内**

- 单页叙事，中文，桌面与移动端（正片在窗口内滚动，页面本身不滚动）
- CRT 终端视觉与随机字符动画
- 无障碍与降级（减弱动态效果、无 JS 兜底、键盘可达）

**范围外**

- 后端、数据库、账号、评论、访问统计
- 照片、视频、背景音乐等媒体素材
- 多语言、多主题切换
- 任何形式的用户输入持久化到服务端
